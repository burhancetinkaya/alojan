## Supported findings

### P2: Browser history navigation discards unsaved agent configuration

`components/agent-editor.tsx:117` guards document unload and anchor clicks, but not
same-document browser history navigation. `components/workspace.tsx` keys the content
by scope and pathname, so leaving the editor destroys its local draft. In Chromium,
open an agent from the list, enable the note tool and edit its guidance, then press
Back: no confirmation appears. Reopening the agent loses both edits. No write was
sent. The existing anchor/unload checks do not cover this execution. Preserve the
draft across history navigation or guard that navigation before destructive unmount.

### P2: Retrying an uncertain agent creation creates duplicate profiles

`components/agent-list.tsx:96` displays the generic retry message and re-enables
creation after a lost response. `alojan/profiles.py:65` creates a new UUID on each
request and has no operation identity to reconcile retries. The new-owner onboarding
flow already blocks blind retry, but the main agent-list modal does not. A real
isolated API accepted the first POST; the browser response was then dropped. Clicking
the enabled create button again produced two distinct database profiles with the same
requested name. Apply uncertainty handling to this modal or correlate repeated
creation attempts with one operation identifier.

### P2: MCP integer configuration silently loses precision

`components/mcp-parameters.tsx:159` immediately converts input through JavaScript
`Number`; `lib/api.ts` serializes the resulting rounded value. An approved integer
schema can have no upper bound. Entering `9007199254740993`, applying and saving sends
`9007199254740992` instead. Chromium reproduced this with the UI's existing mocked
catalog/save boundary; no remote MCP request was made. The schema's integer/minimum
checks do not reject the rounded integer. Reject unsafe integers with an explicit
message or preserve exact integer serialization and parsing throughout the flow.
