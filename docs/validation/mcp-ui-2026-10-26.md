# MCP builder UI validation — 2026-10-26

Task: AGP-07 / M4–M5, ADR 0011, requirements US-08 and §9.3/12/14–16.
Status: implemented and validated as a candidate; not deployed to the serving stack.

## Behavior and review

- Workspace owners can create none/Bearer MCP connections, explicitly request
  discovery, read stored discovery status and confirm connection revocation.
  Credentials are cleared after submission and never returned or put in browser
  storage. Creation and status reads do not contact the remote endpoint.
- Agent editors select only operator-reviewed read capabilities. Per-agent aliases,
  usage guidance and typed fixed parameters are saved in the existing scoped draft.
  Closed reviewed schemas render scalar/enum/object/list inputs; unknown or changed
  tool definitions require a fresh selection. No remote HTML or executable UI schema.
- Exact permission review shows destination, tool, fixed values and remaining
  runtime/output fields. Owners explicitly grant/revoke; editor/viewer UI affordances
  retain role boundaries. API/RLS remain authoritative. Dirty drafts block permission
  submission; stale or lost responses require a fresh review, with no automatic retry.
- Historical active grants stay visible after tools are removed from a draft, so
  their release permission can still be revoked. Replacing a connection requires a
  new reference; already-sent requests cannot be recalled. Publication and number
  binding remain separate from configuration and consent.
- Existing Next.js/shadcn patterns and dependencies are reused. No new service,
  migration or voice-path operation is introduced by this UI change. The existing
  independent web container consumes candidate backend/runtime APIs.
