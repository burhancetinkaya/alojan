# MCP OAuth lifecycle candidate — 2026-10-26

AGP-07 / M4–M5, ADR 0011, US-08 and requirements §9.3/12/14–16.
Ponytail full: reuse the existing management API, discovery worker, bounded transport,
credential encryption, scoped PostgreSQL, native session and Next/shadcn components.
No new service, workflow engine, model or per-agent process.

## Result and review

Implemented operator-pinned preregistered public-client OAuth with PKCE S256, exact
issuer/resource/scope validation, original-session/workspace-bound ten-minute flows,
one-shot code exchange and encrypted rotating access/refresh tokens. Owner review
precedes provider navigation. The callback clears URL parameters, sends no referrer
and completes through the same-origin CSRF-protected API. Account connection does not
authorize tools. Existing discovery/review/grant/release/readiness boundaries remain.
Migration 0023 adds RLS, composite scope keys and immutable identity/state guards.
Management cannot read stored tokens; the executor cannot read refresh tokens.

Renewal runs in the existing separately limited discovery worker. Ambiguous token
rotation and expired claims require reconnection. Readiness requires 30 seconds of
remaining validity and retains the existing two-second permission cache; refresh
never runs in a media callback or tool turn. Revocation/owner loss cannot reactivate
a connection. Review found and fixed two edge cases: short-lived credentials must
renew before the readiness guard, and an in-flight tool result must redact the token
sent before rotation as well as the current token. Both have regression coverage.

The shared HTTPS transport was moved without weakening DNS/IP/TLS, redirect,
compression, method, timeout or size restrictions. Reviewed source/callers/tests,
SQL roles/state transitions, UI callbacks, deployment configuration and full delta
against the turn-start snapshot, including previously untracked project files.

## Remaining gates

A real approved provider and preregistered public client/accepted redirect origin
are not configured. Real-provider login, metadata/refresh interoperability, external
MCP acceptance and coordinated API/worker/executor/web/ingress rollout remain open.
This subset requires S256, issuer response binding, public-client token authentication
and rotating refresh tokens; no dynamic registration, client secrets, automatic scope
expansion or provider-side grant revocation. Local revoke stops Alojan eligibility;
already sent requests and the provider's own authorization cannot be recalled.

Worker backlog/very short expiry fails readiness safely; production load/latency and
carrier acceptance are separate. HTTP/webhook actions (AGP-08) and public-launch gates
remain next independent work. See provider/role/example setup in the management README.
