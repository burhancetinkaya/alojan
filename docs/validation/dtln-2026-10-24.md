# DTLN before Whisper — 2026-10-24

M2-01 / M5-03; requirements §8.1, US-02/06; authorized offline Linux evaluation
under ADR 0003. The owner requested a DTLN trial after reviewing open-source
voice-agent noise filters. No live audio path, default, prompt or service changed.

## Decision

Do not promote either tested DTLN profile. Full suppression worsened human WER
in every condition. A follow-up 50% wet/dry mix improved white-noise and quiet
speech aggregates but regressed ordinary PCMA, fan-like noise, clicks and one
curated product-name case. Low CPU cost does not satisfy the accuracy gate.
No C++ gateway port or carrier rollout is justified by these results.

## Method and verification

Same 24 public FLEURS Turkish read recordings and 16 EMA synthetic fixtures as
the prior denoising study, same deterministic five PCMA/noise/quiet variants,
300 ms lead-in and 200 ms tail, plus three nonspeech controls. Manifest SHA-256:
`dad31c9e7753ae3b0fae450ca872b99852464f02594809ba7bb5b019ef3e7955`.
Source WAV hashes are checked. No private caller audio was used or recorded.

Two separate paired runs: bypass versus full DTLN (406 decodes), then bypass
versus half-strength DTLN (406), totaling **812 real CUDA Whisper decodes**.
Half strength was an exploratory follow-up after full-strength failure, not a
predeclared independent confirmation. All 203 baseline transcripts matched
between runs. Profiles alternate execution order by fixture.

Original [breizhn/DTLN](https://github.com/breizhn/DTLN/tree/1de1f15a8b5b7e1c44905618ff2ef70ca8277fbc)
model pair, commit `1de1f15a8b5b7e1c44905618ff2ef70ca8277fbc`, fixed model hashes
in [the probe](../../tools/denoise-compare/dtln.py), original full suppression.
CPUExecutionProvider, ONNX Runtime 1.31.0, one intra/inter-op thread,
Python 3.12.3 / NumPy 2.5.4 on Intel i5-13600K. Whisper remains the pinned
large-v3-turbo beam-5 Turkish CUDA profile on RTX 4080. Model sessions are reused
and warmed; recurrent state resets per offline utterance.

This is a Python/NumPy driver around native ONNX inference, **not a C++ gateway
benchmark**. The optional half profile blends 50% denoised output with original
speech delayed by exactly 384 samples, preventing phase misalignment. It does
not replicate LiveKit's additional rolloff filter or startup reserve. No AGC,
extra VAD, resampling, spelling correction or second ASR pass was added.

Compared the full processor against the pinned upstream real-time ONNX example
on a deterministic synthetic signal: maximum absolute output difference
`1.2665987014770508e-7` across 15,616 samples. The reference script leaves its
final 384 samples unprocessed; comparison excludes that unused tail. Our probe
processes every hop, pads the partial final hop and preserves original length.
The pre-existing fixture tail retains delayed speech. No retrospective alignment
is applied before ASR.

## Human recognition results

Pooled literal WER; lower is better. Each cell contains 24 recordings / 456
reference words. Number spelling/formatting differences count as word edits,
so these are not percentages of misunderstood meaning.

| Condition | Bypass | DTLN full | DTLN half |
|---|---:|---:|---:|
| PCMA | 11.84% | 20.61% | 12.28% |
| White noise, 10 dB | 32.68% | 66.45% | 29.39% |
| Fan-like noise, 10 dB | 11.18% | 31.36% | 13.60% |
| Click-like noise, 10 dB | 11.84% | 22.81% | 13.60% |
| Quiet PCMA, -24 dB | 32.46% | 42.76% | 31.36% |

Of 120 human condition pairs, full DTLN improved 11, tied 41 and worsened 68
word-edit counts. Half strength improved 28, tied 65 and worsened 27. Those
counts must not be described as equivalent semantic comprehension failures.

For the 80 synthetic condition pairs, full improved 1 / tied 68 / worsened 11;
half improved 0 / tied 77 / worsened 3. The curated product-label miss counts
for PCMA/white/fan/clicks/quiet were respectively 1/2/1/1/1 for bypass,
1/2/2/2/2 for full DTLN and 1/2/2/1/1 for half. Only three product labels per
condition exist; this is not broad name, number or date acceptance.

Digital silence produced empty text in all profiles. Noise-only and hum-only
controls continued to hallucinate stock phrases in both DTLN profiles. These
controls bypass gateway VAD intentionally; denoising is not a substitute for
speech/turn validation. DTLN outputs required clipping on 33 samples at full
strength and 8 at half across the study; clipping is counted, not hidden.

## Cost and delay

| Measurement | Full | Half |
|---|---:|---:|
| Mean work per 8 ms hop | 0.1273 ms | 0.1268 ms |
| Estimated one-core streaming CPU work | 1.59% | 1.59% |
| Maximum per-file P95 hop time | 0.3441 ms | 0.3252 ms |
| Worst observed hop | 1.5743 ms | 0.8747 ms |
| Median whole-utterance Whisper time | 125.3 ms | 122.6 ms |

Each DTLN profile processed 1,861.89 seconds of audio. Timings include the Python
loop, FFTs and both native inference calls; they exclude initialization, warm-up,
file I/O and the final whole-array half-strength mix/clipping. CPU percentages
estimate one core's workload, not total server utilization or hard deadlines.
Bypass median Whisper times were 126.7 / 127.7 ms in the two runs; these small
differences are not evidence of faster phone responses.

The model uses 32 ms windows / 8 ms hops with 24 ms overlap-add signal delay.
A unity-model test verifies exact sample alignment through the processing loop.
Input frame accumulation, packet scheduling and any future adapter buffering
are additional. The 8 ms hop is not the end-to-end delay. Actual phone latency
and real-time C++ integration remain unmeasured. DTLN runs on CPU; only the
temporary offline Whisper comparison instance adds GPU load.

## Checks, artifacts and limits

Linux: **21 focused tests passed in 0.23 s**, including model hash rejection,
finite/range/length boundaries, silence, recurrent-state isolation, exact causal
alignment at full/half strength and existing native-probe checks. One existing
Python 3.12 `audioop` deprecation warning remains. Ruff lint/format and Git diff
whitespace checks passed. Numerical parity used real upstream ONNX models.

Detailed results and models remain ignored under `.local/dtln-eval/`; reproducible
commands and upstream MIT attribution are in the
[comparison README](../../tools/denoise-compare/README.md). No commit/push or
publication was performed. Source changes are limited to offline evaluation
and evidence documentation on `codex/noise-suppression-evaluation`.

The corpus is small, reused, read/synthetic speech with artificial noise. It is
not speaker-balanced, spontaneous telephone speech or carrier acceptance.
No new hardware/transport/soak gate is closed. Standalone C++ integration,
20 ms packet adaptation, cancellation, barge-in, PCMU and handset listening
were intentionally not implemented/tested after the accuracy gate failed.
