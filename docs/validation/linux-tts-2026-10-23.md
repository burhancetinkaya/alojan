# Linux persistent EMA and ASR coexistence — 2026-10-23

Task **M2-02**, requirements §8.2 and §10; supporting M0-03 and cancellation
contracts in §7.4/US-05. Implemented on `codex/tts-service`, preserving the existing
uncommitted M0/M1/M2-01 foundation. No push, publication, merge or license decision.

## Result and scope

One native EMA CUDA worker now stays loaded between requests, warms lightning
once and serves real streaming synthesis on loopback port 15072. The existing
ASR worker remains on 15071. Both report standard gRPC `SERVING` after warm-up.
Source edits/review ran on Mac; all builds, tests, inference and measurements
below ran on the authorized Ubuntu host in `~/ai/alojan` with RTX 4080 (16,376 MiB).

Six synthetic phrases completed concurrent TTS and independent ASR requests.
ASR correctly recovered the established synthetic phone fixture's digits in all
six concurrent checks. The synthesized audio was then separately fed into ASR;
that diagnostic roundtrip exposes a phone-digit error and does not constitute
human intelligibility or WER acceptance. Gateway readiness remains
`voice_pipeline_ready=0`; M2-03 and M3 still own SIP integration, turn decisions,
playback invalidation and sent-audio accounting. G2–G7 remain unpassed.

## Implementation

- `services/tts` has an isolated frozen Linux environment, a checksum-verified
  offline model loader, a persistent worker and standard health service.
  `scripts/run-tts.sh` is the foreground launcher.
- Model and voice match the accepted named greeting: EMA Lightning 1.1.2,
  revision `e7c96f2fc0ba843cd0f86e02786655bb56f50df8`, torch 2.6.0+cu124,
  normalizer-tr 0.8.0, seed zero, lightning batch one. All existing offline
  environment versions were preserved; only the already-used gRPC/protobuf
  dependencies were added. Config and both weight hashes are verified.
- Requests require deadlines and fresh call/generation IDs. Input is bounded to
  512 characters; normalized planning to 2048 model letters/16 pieces; output
  to 30 seconds. One active stream, no inference backlog.
- EMA's float32 output uses its existing stateful resampling to 8 kHz. The service
  converts to PCM16 and emits exactly 20 ms frames, retaining chunk remainders and
  padding only the last frame. Queue capacity is eight frames; write-stall budget
  is 200 ms. One cancellable upstream outbox slot replaces EMA 1.1.2's unbounded
  `SimpleQueue` through a documented, version-specific adapter. Native inference
  and normalization are otherwise unchanged.
- Cancellation closes the iterator and drops queued audio. The slot is not reused
  until native work and scheduler cleanup finish. GPU kernels are not preempted;
  clients must reject stale network-buffered frames before playback.
- ASR and TTS share the existing bounded identity/cancellation helper. A new
  regression demonstrated that an already-cancelled generation could begin a
  write before the previous race checked cancellation. It failed before the fix
  (`context.written == True`) and passed after checking invalidation before any
  operation is scheduled. No ASR decoding/model behavior changed.

## Real GPU evidence

Initial worker warm-up with ASR resident built ten lightning graphs in 20.5 s.
Total host GPU memory sampled every 100 ms peaked at **10,992 MiB**, below the
16,376 MiB device capacity. These are sampled values, not an exhaustive maximum.
The separate numerical calibration recorded PyTorch maxima of 8,471.5 MiB
allocated / 8,640 MiB reserved; these exclude the other process and driver.

Both workers were restarted onto the final code before the final concurrent
run. That run sampled **2,996 MiB total host memory** at peak. Observed process
memory after streaming was approximately 2,336 MiB ASR + 628 MiB EMA, plus driver
usage. There was no observed OOM, model downgrade, CPU fallback or host upgrade.

| Synthetic TTS case | Audio duration | First frame | Complete stream | Concurrent ASR complete |
|---|---:|---:|---:|---:|
| Accepted named greeting | 3.08 s | 84.28 ms | 142.60 ms | 1,414.60 ms |
| Accepted unavailable message | 4.00 s | 13.64 ms | 93.80 ms | 1,369.50 ms |
| Written Turkish date/time | 3.40 s | 7.97 ms | 84.67 ms | 1,351.33 ms |
| Written synthetic phone number | 4.68 s | 11.05 ms | 96.78 ms | 1,369.82 ms |

The first request includes additional first-request overhead. Requests were
unpaced loopback RPCs; overlap is measured at RPC boundaries, not with a kernel
profiler. These are six single observations, not P50/P95, RTP playout latency or
turn-end latency. Native inference and transport costs are combined.

Active explicit cancellation terminated the final run's stream in **0.96 ms**.
A fresh request initially received busy while native cleanup finished, then
succeeded on attempt two after a 50 ms retry wait. Re-cancelling was idempotent;
reusing the cancelled identity stayed rejected. Already-buffered frames were
drained by the validation client until `CANCELLED`; this is not evidence that
caller playout stopped in 0.96 ms or that a GPU kernel was preempted.

## Numerical and text checks

The pinned API produced the greeting at 8/16/24/48 kHz: respectively
24,640 / 49,280 / 73,920 / 147,840 samples, all **3.08 s**. Direct 8 kHz output and
the same seed's 48 kHz output converted with EMA's resampler had maximum absolute
sample difference **0.0**. Uneven resampler input splits also produced identical
samples. This checks state/tail correctness, not comparative listening quality
or a separate 24-to-8 kHz conversion algorithm.

Frontend inspection confirmed Turkish date/time and currency expansion. Foreign
`Zoom` and `Microsoft` normalize to `zum` and `maykrosoft`; `Teams` remains `teams`.
The first calibration incorrectly expected original English spellings and failed
that assertion. The assertion was corrected against the inspected pinned frontend;
no model change or hidden passing substitution was made.

The phone fixture's normalization preserves the intended digits but reads its
trailing full stop as `nokta` under upstream fallback policy. The TTS-to-ASR
roundtrip contained one extra zero; `digits_match` is explicitly **false** in the
ignored evidence. Independent concurrent ASR of the earlier 48 kHz spoken-digit
fixture remained exact in all six cases. This does not isolate the cause to TTS
or ASR and is not a phone-number quality pass. The greeting's surname still splits
into separate words in ASR. Broader pronunciation, punctuation, foreign-word and
number fidelity need labeled/listening evaluation; the owner's earlier accepted
voice remains the existing acceptance, not a new listening approval for these
six phrases.
