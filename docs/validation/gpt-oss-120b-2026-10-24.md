## Authorization and research

The owner requested `openai/gpt-oss-120b`, model-appropriate prompt optimization,
internet research, testing and live activation if faster. The previous DeepSeek
candidate was never deployed and is superseded. The baseline for the comparison
is the last verified live `openai/gpt-6-luna-pro` policy, not DeepSeek.

Research checked on 2026-10-24:

- [Cerebras reasoning](https://inference-docs.cerebras.ai/capabilities/reasoning):
  GPT-OSS supports low/medium/high and cannot disable reasoning. Reasoning consumes
  the output budget. Use low; keep the existing 800-token/step bound for the first
  evaluation, count empty/truncated responses as failures rather than speed wins.
- [OpenAI GPT-OSS reasoning handling](https://developers.openai.com/cookbook/articles/gpt-oss/handle-raw-cot):
  preserve tool-step reasoning inside the SDK run and never expose raw reasoning
  to callers. The existing event filter forwards only speech text. A new test
  injects reasoning before both a note tool call and final text and proves neither
  speech nor first-spoken timing consumes it.
- [Harmony](https://developers.openai.com/cookbook/articles/openai-harmony):
  API providers handle formatting. Do not paste Harmony delimiters into prompts
  or build a second template/stream parser.
- [Reasoning prompt guidance](https://developers.openai.com/api/docs/guides/reasoning-best-practices):
  clear direct instructions, separated sections and examples matching the rules;
  do not demand a step-by-step explanation. This is general reasoning guidance,
  not a measured Turkish-receptionist result for this model.
- [Cerebras tool use](https://inference-docs.cerebras.ai/capabilities/tool-use):
  explicit tool descriptions and strict argument schemas. Existing SDK strict
  tools and application validation remain; note-tool description now explicitly
  distinguishes an actionable message from a topic announcement.
- [OpenRouter provider routing](https://openrouter.ai/docs/guides/routing/provider-selection):
  pin the trial to Cerebras with `only=["cerebras"]`, `allow_fallbacks=false`.
  Apply it to conversation and structured summary requests. Unavailability must
  fail through existing handling, not silently test another host or model.

## Initial prompt changes (superseded by the Hermes-informed revision below)

The rewritten instructions separate role/speech, next-action rules, reception,
tool contracts, six intent examples and trust boundaries. Remove repeated prose;
keep one short question, no readback, no redundant questions, no invented facts,
save-before-optional-contact questions, correction merging and explicit caller
completion before hangup. A topic-only inquiry still gets clarification. A callback
request still saves and invites one addition. An explicit exit without a message
still closes without creating a note. An exit with a correction saves first.

The prompt is roughly 16% shorter by whitespace-delimited words (not tokenizer
tokens). It does not claim that parameter count alone requires a special template.
This is a candidate optimization until real-model behavior is measured.

Applied those principles in original wording: distinguish configured availability
from unknown calendar facts; classify unclear input, topic-only inquiries,
actionable messages and explicit completion; define the next action after a
successful note; distinguish saying goodbye from actually calling `finish_call`;
and supply eight aligned Turkish examples. Tool descriptions reinforce the same
contracts. The current prompt is intentionally more explicit than the initial
shortened candidate. Do not import Hermes coding-agent persistence instructions
into a telephone conversation. No third-party code was executed or installed.

### Method and measured results

Real OpenRouter requests used the actual agent SDK and synthetic Turkish dialogue
fixtures, with in-memory note persistence. No phone recordings or personal
transcripts were sent. Each case used isolated call state and, where relevant,
synthetic prior history and a note. The 18-case suite covers topic clarification,
unclear/unrelated input, availability, callbacks, additions, corrections, mixed
thanks/new requests, refusal and closing. Two cases stop at local guards without
an API request and are excluded from latency statistics, but included in checks.

The baseline loads the earlier prompt/runtime configuration with the verified
live model ID `openai/gpt-6-luna-pro`. Candidate runs use Cerebras-only routing,
low reasoning and 800 output tokens per step unless explicitly noted. This is a
comparison of configurations, not an isolated parameter-count experiment. Runs
were sequential, not randomized or cold-cache measurements. Tests use synthetic
tool persistence, not PostgreSQL, structured summary, ASR, EMA or telephony.

Latency below is time to the first text yielded by `Backend.stream`, including
preceding tool steps where present. It is **not** time to the first complete
speakable phrase or audible handset response. Fast incorrect responses remain
in the timing sample. Automatic checks cover expected note/finish operations,
question count, response bounds, selected facts and correction preservation;
they do not fully assess language or unsupported claims.

Manual review found additional initial-prompt errors not represented in its
automatic score, including claiming the assistant would call and failing to ask
the purpose of an availability inquiry. The revised prompt improved ordinary
topic inquiries and uncertainty wording, but does not establish Luna-equivalent
quality. In a direct single-request probe, the revised prompt asked for the actual
Lena Accredit question without asserting a meeting as fact (first text 688 ms,
completion 888 ms); that probe had no tools and cannot validate call handling.

Critical remaining failures:

- Saving a message/correction followed by explicit goodbye can produce a farewell
  without `finish_call`, leaving the call open.
- After an addition, the model sometimes repeats the invitation already answered.
- Some outputs contain English reasoning or tool-shaped JSON as ordinary speech
  text. Filtering typed reasoning events does not remove content mislabeled as
  ordinary text by the model/provider. The mocked event-isolation test remains
  valid for its limited contract; it is not proof of real-model speech safety.

Private diagnostics did not establish a fix: medium reasoning passed 13/18
checks with one model-behavior exception and observed leakage; Chat Completions
passed 16/18 but still missed closing tools and emitted tool-shaped text. Raising
the per-step budget to 1600 passed only 1/4 hard cases; failed outputs were already
well below 800 tokens, so budget exhaustion did not explain those cases. These
diagnostic settings were not adopted. Current source retains Responses, low
reasoning, the 800-token bound and Cerebras-only routing.

The eight novel paraphrases were prepared before their run. They still exposed
repeat-question and missing-close failures. The Luna sample passed all 18 checks
and manual review of the critical behaviors, which is useful comparison evidence,
not a guarantee of universal correctness. A prompt alone has not closed the gap.

### Decision and scope

Retain the revised prompt as an **undeployed candidate**. The behavior gate fails;
the required paired first-speakable-phrase latency gate is not yet measured.
Do not silently treat a text farewell as a tool call or suppress arbitrary text
to make the evaluation appear successful. Any subsequent orchestration change
needs its own scoped implementation and regression evidence.

Mac regression suite after the revision: **77 passed in 4.56 s**. Ruff check
passed for the agent and affected tests; Ruff format reported 12 files already
formatted, and `git diff --check` passed. The local graph index was refreshed
without exporting an artifact. Credentials,
raw evaluation outputs and diagnostic scripts remain in ignored `.local/` files;
this report contains only sanitized aggregate evidence. Linux synchronization,
live restart, GPU inference and carrier validation were not performed. No push.
