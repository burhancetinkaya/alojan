## Delivered behavior

One persistent large-v3-turbo CUDA float16 model implements the unchanged
`StreamRecognize` and `CancelGeneration` contracts. Turkish replacement hypotheses
are emitted for each additional second of accepted input; half-close finalizes
exactly once. The service validates mono 16 kHz PCM, deadlines, sequences and
identities; caps turns at 30 seconds; rejects overload; and sanitizes model errors.
It has one native inference worker with no application inference queue. Cancelled
or expired results cannot revive, and native work retains capacity until it returns.
See [service semantics and explicit development limits](../../services/asr/README.md).

Standard gRPC health becomes serving only after checksummed offline loading and a
real warm-up decode. The runtime environment is isolated from EMA and root tests.
Model: `dropbox-dash/faster-whisper-large-v3-turbo`, revision
`0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf`; all five file hashes are enforced.
Code pins: faster-whisper 1.2.1, CTranslate2 4.6.0, CUDA cuBLAS 12.4.5.8,
cuDNN 9.1.0.70. Exact package artifacts and licenses are in

## Failures found and fixes

The first real decode used beam size 1 and emitted a hallucinated sentence for
all-zero PCM. It also inserted extra zero digits in the synthetic-number example.
The final worker bypasses decoding only for exact digital silence; quiet nonzero
samples are not discarded. Warm-up calls the native decoder directly so this guard
does not turn readiness into a no-op. Beam size 5 recovered the expected number in
the same fixture, with increased decode time. The original failure is preserved
in ignored `.local/asr-evidence-before-silence-fix.json`; final real results are in
`.local/asr-evidence-final.json` on Linux. No silent correction of output text was
added. Noise/silence hallucination handling is not generally solved by this guard.

The initial full suite had **104 passed, 1 failed, 1 warning in 122.90 s**:
`reorder-only-0` reported one `input_bad_frames`. Six focused transport profiles
then passed in 28.66 s. Source review found that the input meter counted even empty
`PJMEDIA_FRAME_TYPE_NONE` heartbeats as malformed. PJSIP 2.16's conference bridge
emits these when a port is muted or has no transmitter; they are not PCM frames.
The original failure did not record its frame type, so it cannot independently
prove that this was the particular frame observed. The deterministic regression
and fix below address the verified classification bug without relaxing the SIP
assertion that genuinely bad frames must remain zero.

## Final validation

The `input-meter` regression failed before the fix in 1.01 s, proving that a
legitimate empty heartbeat incremented the bad-frame counter. The meter was moved
unchanged into a small reusable header, then given an empty-NONE early return.
Empty/misaligned AUDIO and nonempty NONE remain invalid; silent PCM still counts.
The strict real SIP assertions were not weakened.

Before this fix, a repeat of the unchanged full suite also passed (105 tests,
123.01 s), confirming the original call failure was intermittent. After the
classification fix, the build passed, all 4 CTests passed in 2.06 s, and all 105
