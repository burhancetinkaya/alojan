# M5-01 private Telegram notification preparation

Date: 2026-10-24, Europe/Istanbul. Branch: `codex/telegram-notifications`, based on
`5f03173`. Acceptance mapping: US-07/08, requirements §9.4/11/12. Owner authorization:
automatic post-call notifications to their Telegram bot; previous deferral superseded.

## Changes

Standalone worker, additive migration, fixed private recipient pairing, bounded
plain-text summaries, status-only fallback, durable outbox/retries and user-service
template. No new dependency, LLM call, agent prompt or media behavior. Caller and
model text cannot choose recipients or invoke Telegram operations. The bot token
and paired chat file are ignored private configuration. No old-call backfill.

Mac Ruff lint and format checks passed for both new modules and their tests.
No native/GPU or voice regression suite was rerun: those sources were not changed.

## Remaining acceptance and limitations

Bot credentials were not configured during these checks. Pairing with the real
owner, the synthetic Telegram message, channel activation and a real completed
phone call remain pending. No notification was sent and no voice service restarted.
The production database migration has not been applied; only isolated test schemas
were migrated. No Git push or PR was performed for this feature.

Telegram has no sendMessage idempotency key. Failure after remote acceptance but
before recording the receipt can cause a duplicate on retry. Permanent errors or
12 failures retain a failed row for owner/operator review; no retry dashboard/API
is included. Summary quality, calls missing their persisted end event, deployment
across host reboot and full G5 carrier acceptance remain separate checks.
See [operation, configuration and rollback](../TELEGRAM.md).
